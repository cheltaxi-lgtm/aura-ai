# ТЗ: Каталог раскладов Zovus

> Основано на анализе [КП: лучшие схемы раскладов Таро](https://www.kp.ru/woman/goroskop/luchshie-skhemy-raskladov-taro/) и текущей архитектуры продукта (июнь 2026).

## 1. Проблема

Сейчас почти все сеансы используют **одну схему — 3 карты** с позициями «Прошлое / Настоящее / Будущее» (или «Утро / День / Вечер» для карт дня). Тема вопроса меняется, **геометрия расклада — нет**.

Исключение: обряды (5 карт: Суть / Блок / Ресурс / Действие / Итог).

Пользователь не может выбрать «быстрый» (1 карта), «стандартный» (3) или «глубокий» (5–10) расклад. Конкуренты и SEO-трафик (КП, Woman.ru) ориентированы именно на **названные схемы**.

## 2. Цель

Добавить **каталог раскладов** с выбором схемы перед сеансом, сохранив текущий UX как дефолт и не ломая биллинг/чат.

### KPI (ориентиры)

- Конверсия «выбор темы → старт сеанса» не падает более чем на 5%.
- Средний чек (руны) растёт за счёт «глубоких» раскладов (+15–25% к ARPPU сеанса).
- SEO-лендинги под запросы «расклад таро на 3/5/10 карт», «кельтский крест онлайн».

## 4. Целевое состояние (to-be)

### 4.1. Модель данных

```ts
// src/lib/spreads/types.ts (новый)
type SpreadId =
  | "triplet"           // дефолт, as-is
  | "single"            // 1 карта
  | "situation-5"       // крест 5 карт (КП)
  | "celtic-cross"      // 10 карт
  | "love-7"            // «Волшебная любовь»
  | "yes-no"            // 1–3 карты
  | "daily-extended";   // 7–8 карт «на день» (опционально, фаза 3)

interface SpreadDefinition {
  id: SpreadId;
  label: string;
  description: string;
  cardCount: number;
  positions: { key: string; label: string; hint?: string }[];
  /** Какие темы сеанса поддерживает */
  topics: SessionTopicId[] | "*";
  /** Какие deck systems */
  systems: DeckSystem[] | "*";
  /** Множитель стоимости относительно triplet (1.0) */
  costMultiplier: number;
  /** Доступен без регистрации / только premium */
  access?: "free" | "registered" | "paid";
  seoSlug?: string;
}
```

Реестр: `src/lib/spreads/registry.ts` — единый источник правды для UI, API, промптов.

### 4.2. UX-flow

```
Выбор мастера
  → Выбор типа: «Карты дня» | «Новый расклад»
  → [НОВОЕ] Выбор схемы (карточки: 1 / 3 / 5 / 10)
  → Выбор темы (фильтр по spread.topics)
  → Flip / ritual loader
  → Чат с мастером
```

- **Карты дня** — без изменений в фазе 1 (3 карты).
- **Новый расклад** — схема по умолчанию `triplet` (обратная совместимость).
- Глубокие расклады (5+) — badge «Глубокий», цена ×1.5–2.5.

### 4.3. Backend

| Изменение | Детали |
|-----------|--------|
| `POST /api/intention-spread` | Поле `spreadId`, draw N карт, positions из registry |
| `drawIntentionSpread` | Принимает `count`, не хардкод 3 |
| `buildSpreadBlock`, `spread-instructions.ts` | Генерация промпта по `SpreadDefinition`, не только 3 блока |
| `sessions` / `chat_meta` | Сохранять `spreadId` + `cardCount` |
| `platform_settings.features` | Опционально: включение схем в админке (как reCAPTCHA scopes) |

### 4.4. UI

- `SpreadPicker` — grid карточек с иконкой схемы, числом карт, кратким описанием.
- `SpreadLayout` — универсальный компонент раскладки (замена жёсткого triplet grid).
- Кабинет: история с подписью схемы («Кельтский крест · Любовь»).

## 5. Фазы реализации

### Фаза 1 — MVP каталога (2–3 недели)

**Scope:** 3 схемы без смены daily flow.

| ID | Карт | Позиции | Приоритет |
|----|------|---------|-----------|
| `triplet` | 3 | Прошлое / Настоящее / Будущее | as-is |
| `single` | 1 | Послание дня / Ответ | быстрый вход |
| `situation-5` | 5 | Ситуация / Препятствие / Корень / Совет / Итог | первый «глубокий» |

**Задачи:**

1. `SpreadDefinition` + registry + unit-тесты позиций.
2. Рефактор `intention-spread` route: `spreadId`, dynamic count.
3. `SpreadPicker` в `MasterSessionFlow` после «Новый расклад».
4. Динамический промпт (N секций вместо 3).
5. Биллинг: `cost = baseSpreadCost * spread.costMultiplier`.
6. Миграция: `spread_id` в session meta (nullable, default `triplet`).

**Не делаем:** кельтский крест, SEO-страницы.

### Фаза 2 — Тематические позиции + 7 карт (2 недели)

| ID | Карт | Особенность |
|----|------|-------------|
| `love-7` | 7 | Позиции «Волшебная любовь» (КП), только topic `love` |
| `triplet-love` | 3 | Вы / Партнёр / Перспектива — альтернатива triplet для love |
| `yes-no` | 1 | Да/Нет/Не сейчас (таро only) |

- Topic-aware positions: при `love` + `triplet` подменять labels.
- Промпты мастеров: блок «позиции для темы X».

### Фаза 3 — Кельтский крест + SEO (3 недели)

| ID | Карт |
|----|------|
| `celtic-cross` | 10 |

- Сложная вёрстка (крест + столб), mobile scroll/zoom.
- Отдельные лендинги `/rasklad/keltskij-krest`, `/rasklad/na-lyubov` (SSG).
- Schema.org FAQ из позиций расклада.

### Фаза 4 — Админка и A/B (1 неделя)

- `/admin/settings` → блок «Расклады»: вкл/выкл схем, множители цены.
- Метрики: `spread_selected`, `spread_completed`, revenue per spreadId.

## 7. Риски

| Риск | Митигация |
|------|-----------|
| LLM «раздувает» ответ на 10 карт | Лимит токенов + сокращённые блоки для 5+ карт |
| Mobile UI для 10 карт | Компактная схема, поэтапный flip |
| Слом старых сессий | `spreadId` nullable → `triplet` |
| Стоимость API | Множитель цены + cap вопросов в сеансе |

## 8. Критерии приёмки (фаза 1)

- [ ] Пользователь выбирает схему перед темой; triplet работает как раньше.
- [ ] `situation-5` рисует 5 уникальных карт с правильными позициями.
- [ ] Первое сообщение мастера ссылается на все N позиций.
- [ ] В истории/кабинете видна схема расклада.
- [ ] Стоимость в рунах соответствует множителю.
- [ ] Guardrails + TypeScript без регрессий.
